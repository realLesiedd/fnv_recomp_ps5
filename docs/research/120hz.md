# 120 Hz and 40 fps (#4)

A plan, parked until the sync-state work and the x87-in-locals work are done. Nothing in this note is implemented. It does not change code or `ps5/sce_sys/param.json`.

The goal is 40 fps on a 119.88 Hz output. The frame cap stays at or below 60. `rt/osd.c` already refuses to run the game faster than 60, because the physics break above that.

## What the pinned driver does

[ps5-plume-triangle `d54d9ad`](https://github.com/Nazky/ps5-plume-triangle/blob/d54d9ad/tools/build-radv.sh) builds RADV from source. `make` builds the sample app (`tools/build.sh`). On a fresh checkout that script runs `tools/build-radv.sh`. The script's `mesa_revision` is `0b2d6d1a61d9bbf89cf8beb88a696144f67c61f8` (short form `0b2d6d1a61d`). It checks that revision before it builds. `PS5_MESA_FORK` can point the clone at another tree.

At that revision, [`wsi_common_videoout.c`](https://github.com/mihawk-99/PS5_Mesa/blob/0b2d6d1a61d9bbf89cf8beb88a696144f67c61f8/src/vulkan/wsi/wsi_common_videoout.c) already knows a 119.88 Hz mode (`VIDEOOUT_HIGH_REFRESH_MILLIHERTZ` is 119880). It offers that mode only when `param.json` `attribute3` has every bit in `0x80040`. The test is `(value & 0x80040) == 0x80040`. Our [`ps5/sce_sys/param.json`](../../ps5/sce_sys/param.json) has `"attribute3": 0`, so today's driver does not offer the mode.

The flip rate is hard-coded. `videoout_register_locked` calls `sceVideoOutSetFlipRate(handle, 0)`. `wsi_videoout_set_flip_rate` is absent from that file.

The same file already calls `sceVideoOutSetFlipRate`, `sceVideoOutIsOutputSupported` and `sceVideoOutConfigureOutput`. Those are inside the static RADV archive `ps5/build.sh` links. They are not new imports for this app to declare. The team reports that a v40 boot on 13.42 already gets past them, because the app starts. This note did not re-test that.

If the title declares the high-frame-rate bits, the driver asks VideoOut for the high mode and then measures the vblank period. A period above 12.5 ms (`VIDEOOUT_HIGH_REFRESH_LIMIT_NS`, 12500000) is treated as a display that stayed at 60 Hz, and the driver restores 59.94 Hz. That is the only check. The host stub in the same file names the high mode `15`. The 13.42 console header is not in this repository. Whether 13.42 grants mode 15 is **unconfirmed**.

## Later Mesa commits

Three commits, all on `src/vulkan/wsi/wsi_common_videoout.c`. The published diffs add up to +36/−5 (28/−2, then 4/−1, then 4/−2). They were not applied onto `0b2d6d1a61d` here, and they were not built. The team reports the apply is clean. That apply is **unconfirmed** until someone does it.

- [`aa44fa40bc5`](https://github.com/mihawk-99/PS5_Mesa/commit/aa44fa40bc5) adds `wsi_videoout_set_flip_rate`. The rate is 0, 1 or 2: each flip is shown for 1, 2 or 3 vblanks. At 119.88 Hz, rate 2 is even 40 fps and rate 1 is 60.
- [`f46af724514`](https://github.com/mihawk-99/PS5_Mesa/commit/f46af724514) lets a process with no `/app0` name its `param.json` in `PS5_VIDEOOUT_PARAM_JSON`. Our app has `/app0`, so this is for the build, not for the console path.
- [`12d03913d06`](https://github.com/mihawk-99/PS5_Mesa/commit/12d03913d06) changes the gate from `0x80040` to `0x40` alone. Its comment says the `0x80000` bit turns system VRR off, and that VideoOut itself grants or refuses mode 15.

The team says later commits add 1440p and 1080p modes. Those commits were not read for this note. **Unconfirmed.**

GitHub's compare of the pin to `f5610fe2709` is not a straight line. It reports 127 commits ahead and 103 behind (the histories diverge). Bumping to that commit was rejected. It is more risk than the three cherry-picks. Where a fork branch would be hosted is an open question for the owner.

## Plan

Chosen approach: keep `0b2d6d1a61d` and cherry-pick the three commits above. Point `build-radv.sh` at that fork with `PS5_MESA_FORK`, and set `mesa_revision` to the new commit. The script checks the revision, so a stale tree will not be reused.

1. **RADV.** Fork branch at `0b2d6d1a61d`, plus `aa44fa40bc5`, `f46af724514` and `12d03913d06`. One file, as above. Reported clean, not built.
2. **`attribute3`.** In `ps5/sce_sys/param.json`, change `0` to `0x40` (64). Not `0x80000`. This reaches every player. A 120 Hz TV may then run at 120 Hz even while the cap is 60. **Unconfirmed.** With today's RADV the gate is still `0x80040`, so `0x40` alone changes nothing until the cherry-pick is in the driver.
3. **Mode choice.** `createSurface` in `ps5/dxvk/dxvk-ps5.patch` logs every mode and prefers 3840x2160 near 60 Hz (`refreshRate` from 59000 to 61000 millihertz). It already stores the chosen refresh in `g_ps5RefreshMilliHz`. When 40 fps is on, pick the 4K mode near 119880 millihertz. Otherwise keep the near-60 choice.
4. **Flip rate.** Declare `wsi_videoout_set_flip_rate` as a weak extern and check for null. If it is missing, log that, stay on 60, and hide 40 FPS. Call it before the first present. Rate 2 for the 40 cap. Rate 1 when the output is 120 Hz and the cap is 30 or 60. Never rate 0 at 120 Hz. Rate 0 is what the pinned file does today, on every output.
5. **Limiter.** `g_frame_cap` in `rt/osd.c` is 30 or 60. `osd_init` turns any other value into 60. `osd_frame_limit` waits `1/30 - 0.0002` or `1/60 - 0.0002` seconds. Accept 40, with period `1/40 - 0.0002`. Still never above 60. Add a `40 FPS` choice to Frame Rate Cap in `rt/options.c` (today the row is `30 FPS` and `60 FPS`, and `cap_set` writes only those). Offer 40 only if the driver took 119.88 Hz. `iFrameCap` in `rt/firstrun.c` is documented there as 30 or 60 and defaults to 60. Accept 40.
6. **No new PS5 import.** The three `sceVideoOut` calls above are already in the pinned RADV file.

## What to test

The owner, on a PS5. A 120 Hz TV with 120 Hz output on, at the 60 cap and at the 40 cap. Then a 60 Hz TV, to see the fallback.

In `_d3d9.log`, the `PS5 WSI: mode` lines and the `PS5 WSI: TV mode` line. Those are DXVK logs from `createSurface`. `rt/hostd3d9.cpp` sets `DXVK_LOG_PATH` to the app folder. The `wsi/videoout:` lines are `fprintf(stderr)` in the Mesa file. This app sends stderr to `fnv.log` (`rt/main.c`), so those lines are expected there, not in `_d3d9.log`. **Unconfirmed** on a console log. Also the `perf:` fps line in `fnv.log`.

## Unconfirmed

- Whether 13.42 grants mode 15. That needs a 120 Hz TV and 120 Hz output turned on.
- What happens if DXVK still picks the 59.94 Hz mode while the output is at 120 Hz. The pinned driver only checks that the vblank period is not above 12.5 ms.
- Whether `0x40` makes a 120 Hz TV stay at 120 Hz under a 60 cap.
- Whether the three commits apply cleanly on the pin, and whether that tree builds. Not done here.
- Later 1440p and 1080p modes. Not read here.
